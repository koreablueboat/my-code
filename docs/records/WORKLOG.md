두 traceback은 사용자 구독 콜백에 들어가기 전 메시지를 가져오는 단계에서 끝난다. 시험 실행기는 자식 프로세스 그룹에 SIGINT를 보낸다. 현장 traceback에는 당시 토픽이나 신호 도착 시각이 없다. Humble의 typed subscription은 RMW에서 가져온 메시지를 Python 객체로 변환한 뒤 executor에 반환한다. [Humble subscription 구현](https://raw.githubusercontent.com/ros2/rclpy/humble/rclpy/src/rclpy/subscription.cpp)

**재현 방법.** 로컬 시험 도메인에서 유효한 합성 `Int32MultiArray`(CH5 KILL·SB MANUAL)를 ROS로 발행했다. 수신 메시지 생성자에 관찰 지점을 두고 실제 `_take_subscription`에서 객체를 생성하는 순간 OS SIGINT를 보냈다. 시험이 예외를 직접 발생시키지는 않는다. 수정 전 두 노드 모두 현장과 같은 traceback 및 종료코드 1을 재현했다. 시점을 맞추지 않은 SIGINT 대조에서는 둘 다 종료코드 0이었다. 합성 시험은 이 타이밍이 오류를 일으키는 충분조건임을 보여 준다. 현장 두 건의 정확한 메시지 타입과 신호 시점은 미확정이다. [재현·회귀 시험](../../rc_preview_trial/test_receive_shutdown.py) · [합성 시험 로그](../../rc_preview_trial/results/synthetic_shutdown_20261125/)

**수정.** 수정 전 파일을 백업하고 제어기와 표시 노드의 진입점만 변경했다. 두 노드는 SIGINT·SIGTERM에서 종료 요청을 표시하고, 진행 중인 수신 처리가 반환되면 executor 루프를 빠져나온다. 유휴 대기는 최대 50 ms이며, 제어기는 정리 단계에서 기존 정지 상태와 영명령을 발행한 뒤 ROS 컨텍스트를 닫는다. 일반 수신 오류는 계속 호출자에게 전달한다. [백업](../../backups/before-ros-take-shutdown-20261125.tar.gz) · [제어기](../../src/kaboat_control/scripts/control.py) · [표시 노드](../../rc_preview_trial/axes.py)

**회귀 결과.** 수정 전에는 유효 프레임 20개 이상 수신 후 변환 중 SIGINT를 보내면 제어기 3/3회, axes 3/3회 모두 같은 오류로 종료했다. 수정 후 두 노드에서 수신 사이 SIGINT, 변환 중 SIGINT, 변환 중 SIGTERM의 6개 조합 모두 종료코드 0이었다. 제어기의 종료 시 estop=true 및 선속도·각속도 0 발행도 확인했다. 기존 데드밴드 진행 시험 3/3과 메모리 어댑터 결함 시험 6/6이 통과했다. 3개 패키지 빌드 성공, 전체 colcon 집계 127건에서 오류·실패·건너뜀은 모두 0건이었다. 이번 회귀에는 합성 입력만 사용했다. [종료·데드밴드 시험](../../rc_preview_trial/results/synthetic_shutdown_20261125/regression.log) · [메모리 어댑터 시험](../../rc_preview_trial/results/synthetic_shutdown_20261125/fake.log)
