# 2026년 11월 24일 RC 보트 제어 경로 검토

ROS 2 Humble에서 RC 수신, 수동·AUTO 명령 선택, 좌우 추진기 명령 생성까지 PREVIEW로 점검했다. 실물 시험 전 첫 수정 대상은 모터 명령 수신이 끊긴 뒤 재무장 없이 출력이 이어지는 경우다.

| 점검 | 결과 |

| 임시 디렉터리 클린 빌드 | boat_rc, kaboat_control, kaboat_motor 모두 성공 |

| 합성 RC 통합시험 | 6개 중 5개 통과. AUTO 재무장 중 auto_command_timeout으로 KILLED 상태가 됐다. [전체 실행 로그](evidence/2026-11-24/preview.log) |

| CTest 등록 | 세 패키지 모두 등록된 시험 0개 |

## 개선 순서와 확인 기준

1. **모터 명령 단절 처리.** 마지막 명령 후 0.79초 뒤에 새 명령을 받고 타이머를 실행하자 두 제어기 모두 무장을 유지하고 좌우 논리 출력이 0.045가 됐다. 수신 시각 갱신 전에 단절 여부를 확인하고, 타이머와 수신 콜백의 실행 순서를 바꿔도 재무장 전까지 출력이 0인지 검사한다. [모터 코어](../../../src/kaboat_motor/motor_core.py) · [양방향 PREVIEW 코어](../../../src/kaboat_motor/reverse_motor_core.py)
2. **양방향 추진기 규칙.** 제자리 회전 입력 (0, 0.06)에서 PREVIEW의 좌우 목표는 (−0.04, +0.04), 실물용 코드의 목표는 (−0.10, +0.10)이었다. 0.40초 방향 전환 중립 유지도 PREVIEW에만 있다. 실제 ESC 사양으로 후진 한계와 중립 시간을 정한 뒤 모의 PCA 경로에서 같은 시나리오를 검증한다. [제어기 선택 코드](../../../src/kaboat_motor/boat_motor_node.py)
3. **실물 정지 검증.** 채널 매핑은 확인됐지만 RF 단절 반응, Pi 정지 시 독립 차단, 실제 PWM과 추진기는 이번 점검에서 실측하지 않았다. 추진 전원을 분리한 벤치에서 송신기 단절과 Pi 정지를 각각 시험하고 RC·LQ, 출력 차단 시점, 복구 후 재무장 여부를 기록한다. [RC 설정](../../../src/kaboat_control/scripts/control_config.json) · [모터 설계 문서](../../../src/kaboat_motor/README.md)
4. **회귀시험 자동화.** 기존 시험을 colcon test에 등록하고 통합시험이 활성 설치 경로에서 실행 파일을 찾도록 한다. AUTO 간헐 실패를 추적할 수 있도록 마지막 명령 수신 시각과 상태 전이 사유를 남긴다. [통합시험 코드](../../../src/kaboat_control/test/preview_integration.py)
5. **자율주행 명령 경로 문서화.** 모터 README는 회피 노드에 /boat/cmd_vel 직접 발행을 안내한다. 통합 구성에서는 에이전트가 /boat/auto/cmd_vel에 발행하고 kaboat_control이 /boat/cmd_vel의 단독 발행자가 되어야 한다. 두 패키지의 안내를 이 경로로 통일한다. [모터 안내](../../../src/kaboat_motor/README.md) · [제어 안내](../../../src/kaboat_control/README.md)
